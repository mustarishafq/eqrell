## Root cause (two layers)

1. **Source (primary, durable fix):** `app/display/page.js` calls `useSearchParams()` that is NOT inside a React `<Suspense>` boundary. In Next.js 15, when a route is statically prerendered, an unwrapped `useSearchParams()` triggers a CSR bailout that is a hard build error (`missing-suspense-with-csr-bailout` → `prerender-error`). The recent `/display` edit (loaded/error state + 15s fetch timeout) fixed the runtime loading-splash hang but did NOT add the required Suspense boundary. This compiles fine in Turbopack `next dev` (no static prerender), which is why preview looked healthy — the error only appears in the production `next build` export.

2. **Platform regression (why the safety net didn't save it):** The default template Dockerfile has an auto-fix step that is supposed to wrap unwrapped `useSearchParams` pages in Suspense at build time. It uses `grep -P` (Perl regex). The last good builds ran on an **amd64** builder (GNU grep, `-P` supported) so the band-aid silently wrapped the page. These failing runs switched to an **arm64** builder whose grep is **BusyBox v1.37.0**, which does not support `-P` (`grep: unrecognized option: P`). The script therefore "Could not find component name in /app/app/display/page.js" and skipped it, exposing the latent source issue. `/auth/callback`, `/kid`, `/world` already contain explicit Suspense in source, so they were skipped before reaching the broken grep path — only `/display` hit it.

## Fixes

### Code (E1) — primary
In `app/display/page.js`, move the `useSearchParams()` call into a child component and render it under a Suspense boundary, e.g.:
```jsx
import { Suspense } from 'react';
function DisplayInner() {
  const searchParams = useSearchParams();
  // ...existing /display logic...
}
export default function DisplayPage() {
  return (
    <Suspense fallback={<LoadingSplash />}>
      <DisplayInner />
    </Suspense>
  );
}
```
Alternatively, opt the route out of static prerender by adding `export const dynamic = 'force-dynamic'` (or `export const dynamicParams = true` is not sufficient — use `force-dynamic`) at the top of `app/display/page.js`. The Suspense wrap is preferred as it keeps the route statically optimizable. After the edit, redeploy.

### Platform — secondary (escalate)
The template Dockerfile's auto-Suspense-wrap step relies on `grep -P`, which is unavailable on the arm64 BusyBox builder image now used for this deployment (previous successful builds were amd64 with GNU grep). The band-aid should be made busybox-compatible (e.g. `grep -E` with an equivalent pattern, or a node/awk parse) or the builder image should ship GNU grep. This is a deployer-side regression, not the user's app — I could not patch it myself because this is a non-farm template (`nextjs_mongo_shadcn_base_image`) with no manifest override in GCS, and authoring the full manifest set would require fabricating files I have no authoritative source for.
